MUSB core suspend/resume context backport
========================================

Implementation reference
------------------------
The context layout and save/restore coverage are adapted from Linux v2.6.39:
https://github.com/torvalds/linux/blob/v2.6.39/drivers/usb/musb/musb_core.c
https://github.com/torvalds/linux/blob/v2.6.39/drivers/usb/musb/musb_core.h

This is an adaptation to 2.6.32.44, not a direct application of stable commit
262e2d9d559334e09bc80516132ea99d82f97b8c.  The local tree uses
musb->config->dyn_fifo and has no upstream FIFO/target read helpers or ULPI
bus-control accessor.  Reads therefore use this tree's register definitions.
FRAME is a read-only frame counter and is not restored.  FADDR is included
for peripheral and single-point host operation.  Host type, interval and
multipoint target state is guarded by CONFIG_USB_MUSB_HDRC_HCD; Blackfin's
fixed FIFOs and absent multipoint registers are excluded at compile time.

Only initialized, configured endpoints are visited, bounded by nr_endpoints
and MUSB_C_NUM_EPS.  EP0 uses CSR0 and host TYPE0/NAKLIMIT0, without accessing
its reserved nonzero-endpoint registers.  Both helpers explicitly select
INDEX, including on flat-register platforms where FIFO setup remains indexed,
and restore the pre-suspend INDEX after their loops.  Dynamic FIFO size and
address state includes double-buffer configuration.  Static FIFO layout is
hardware-defined and is not written.

Save runs under the existing lock before clock disable.  On the core-only
path restore runs in resume_noirq after set_clock/clk_enable succeeds.
The OMAP3430 follow-up uses the sleepable resume sequence described below.
The clock failure return is retained, so failure performs no core register
accesses.
FIFO layout and host routing precede endpoint CSR restoration; controller
interrupt enables are restored last.  musb_dma_completion is unchanged.

OMAP wrapper and PHY follow-up (depends on #57)
----------------------------------------------
Dependency: https://github.com/palmbeach05/shadow-kernel/pull/57
This follow-up adds system PM recovery for cpu_is_omap3430() builds using
CONFIG_ARCH_OMAP3430 and CONFIG_PM.  The Makefile also selects omap2430.c
for CONFIG_ARCH_OMAP2430, but that variant retains the core-only PM path:
its retention and external PHY requirements have not been verified here.
OMAP4 and other integrations are outside this driver's selected hardware.

Hardware reference: TI OMAP35x TRM SPRUF98Y, sections 23.1.3.1,
23.1.5.1, 23.1.5.4 and tables 23-11, 23-15 and 23-19:
https://www.ti.com/lit/ug/spruf98y/spruf98y.pdf
The controller belongs to the CORE power domain; hardware reset resets the
whole module.  Its functional clock comes from the external ULPI PHY.
The supported interface is 12-pin SDR ULPI.  Wrapper recovery uses 32-bit
accesses, releases ENABLEFORCE before changing idle modes, and separates
AUTOIDLE enable from idle-mode programming.  Revision/status registers are
read-only; SIMENABLE is simulation-only and must not be replayed.  The image
contains SYSCONFIG without SOFTRESET, INTERFSEL PHYSEL, and FORCESTDBY
ENABLEFORCE.  It preserves the tree's OMAP3430 AUTOIDLE workaround rather
than imposing the manual's generic smart-idle policy.

The implemented sequence is:
1. In regular suspend, disable/synchronize the controller IRQ and the separate
   Inventra DMA IRQ, if allocated.  Cancel the idle timer and initialized OTG
   timer synchronously, remembering pending deadlines.  Save core registers
   under musb->lock while the clock is still enabled.
2. After unlocking, save wrapper configuration, request force standby/wakeup,
   suspend the transceiver and release the interface clock once.  These new
   system PM callbacks do not call the init/exit platform suspend helper.
3. Skip the core resume_noirq work on this OMAP path.  In regular resume,
   acquire the interface clock once, restore wrapper access and PHYSEL, then
   the saved idle/standby policy.  Flush wrapper writes and resume the PHY.
   Only then restore core context under the lock, rearm pending timers and
   enable the IRQs.  Expired timers are scheduled for the next tick.

The otg_set_suspend API explicitly permits sleeping.  TWL4030 uses I2C and
regulators and restores PHY power, clocks and ULPI mode; these operations
must run outside musb->lock and outside noirq.  CPCAP and NOP transceiver
set_suspend callbacks are no-ops in this tree.  They provide no evidence of
PHY recovery after power loss.  There is no generic ULPI register image or
PHY-ready polling here: callback success is the readiness contract.  In
particular, TWL4030 currently hides some I2C/regulator failures by returning
zero.  The platform must also resume the PHY's I2C/regulator suppliers before
this callback; this old API does not establish device dependency links.

Clock-enable failure returns before wrapper or core MMIO.  PHY-resume failure
keeps IRQs/timers quiesced, requests standby and releases the acquired clock;
core restore is skipped.  Clock ownership is tracked so retries do not acquire
a duplicate reference.  Suspend errors attempt wrapper/PHY rollback and only
unquiesce after successful rollback; rollback failure is logged.  A failed
resume must be retried before another suspend can save context.  The existing
OMAP clock callback reports failure without changing clock state.  During
initialization the clock is already on, so the old second enable is removed.
Other platforms keep their existing clock ownership and resume_noirq path.

This is untested off-mode recovery support, not evidence of working off-mode
USB.  Normal clock gating does not prove context loss or PHY recovery.  FIFO
contents, in-flight DMA state, pad mux/PRCM restoration, PHY-specific state
not recovered by set_suspend, and wrapper state on other platforms (including
TUSB6010) remain outside this image.  Transfers must already be quiescent.
Remote wakeup and board-specific power sequencing require hardware validation.

Validation record
-----------------
Core backport inspection record (from #57):
- AST outlines of musb_core.h, musb_core.c and omap2430.c before source review.
- Static preprocessor/AST checks of the added structures and helpers with PM
  on/off, host support on/off, and normal, Blackfin and TUSB6010 register
  guards (12 combinations).  Checked register macro availability and matching
  saved/restored fields.  These checks are not kernel compilation or tests
  of register behavior.
- Static review of endpoint bounds, INDEX selection/restoration, FIFO and
  interrupt ordering, and the clock-enable failure path.
- Verified musb_dma_completion and existing OMAP clock error handling remain
  unchanged; git diff --check passed.

Follow-up inspection completed:
- Reviewed AST outlines, OMAP variant selection, wrapper register definitions,
  clock callback ownership/error semantics, transceiver implementations,
  controller/DMA IRQ registration and idle/OTG timer callers.
- Reviewed the TI hardware reference above and checked PM callback ordering,
  CONFIG_PM/CONFIG_ARCH_OMAP3430 guards and non-OMAP fallback by source review.
- git diff --check passed.  No repository code was executed.

No kernel builds or hardware tests were run.  Required follow-up with a
suitable toolchain and target configuration:
- Build OMAP2430 and OMAP3430/OMAP34XX host-only, peripheral-only and OTG
  configurations with CONFIG_PM=y, plus host/peripheral CONFIG_PM=n builds.
  Cover CONFIG_MUSB_PIO_ONLY and CONFIG_USB_INVENTRA_DMA where supported.
- Build DaVinci static FIFO and TUSB6010 dynamic FIFO configurations, and
  Blackfin fixed FIFO configurations, with host/peripheral and PM guards.
  Full builds may expose pre-existing issues: without CONFIG_HAVE_CLK the
  local clk_enable stub expands to a statement, whereas the inherited
  resume error handling assigns its result.  This unrelated stub is unchanged.
- Check normal host enumeration and transfers, including a downstream hub
  for multipoint routing, and peripheral enumeration and data transfers.
  Exercise OTG roles, supported speeds, endpoint directions, PIO and DMA.
- Repeat suspend/resume with a connected device, disconnected cable and idle
  controller; check transfers afterward, wakeup where supported, interrupt
  behavior, nonzero INDEX preservation, FIFO layout and clock balance.
  Inject clock-enable failure and confirm its error reaches the PM caller
  without register accesses, then check recovery on a later successful resume.
  Inject PHY suspend/resume and clock-disable errors; check rollback, retained
  IRQ/timer quiescence on recovery failure, and one clock reference per active
  controller.  Check both allocated DMA IRQ and PIO-only configurations.
  Confirm I2C/regulator suppliers are available before the PHY callback and
  check for sleep-in-atomic/IRQ warnings.  Exercise pending idle/OTG timers.
- Separately force real off-mode context loss and verify it occurred using
  platform power-state evidence.  Check wrapper, PHY, core and endpoint
  register recovery and USB operation over repeated cycles.  Clock gating
  alone does not demonstrate context-loss recovery.  Record silicon revision,
  board/PHY, role, CORE previous power state and recovered wrapper values;
  distinguish OMAP3430 results from the unchanged OMAP2430 path.  A no-op PHY
  callback cannot establish recovery after external PHY power loss.
