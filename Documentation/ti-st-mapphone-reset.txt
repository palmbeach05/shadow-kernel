MAPPHONE TI Shared Transport reset ownership
============================================

Change description for the reset ownership PR
---------------------------------------------
Remove the MAPPHONE chip_enable/chip_disable assignments and their private
reset helpers. They duplicated KIM's GPIO reservation and startup/shutdown
reset sequences, including treating an already reserved GPIO as available.
KIM is now the sole reset owner for the MAPPHONE WiLink selection.
wilink_pdata.nshutdown_gpio remains MAPPHONE_BT_RESET_GPIO (GPIO 179).

KIM still requests the GPIO at probe, configures it output-low, and frees it
on probe unwind or removal. Startup remains low for 5 ms then high for
100 ms; shutdown remains low/high/low with 1 ms delays between transitions.
The alternative non-WiLink/rfkill branch is unchanged. Generic platform
callback error propagation is deferred to a separate PR. Suspend/resume
callbacks and UART sleep/wake handling are unchanged; host-wake behavior
remains unverified. No suspend/resume reset pulses are added.

Source inspection and base limitations (2026-10-24)
--------------------------------------------------
Inspected AST outlines before focused source slices of board-mapphone.c,
st_kim.c and ti_wilink_st.h. The removed board helpers contain only GPIO
reservation, direction setup, reset pulses and private reservation bookkeeping;
there are no additional regulator, clock or pin-mux operations to retain.
Repository-wide reference inspection found no external users of the helpers.
KIM's request, direction, start, stop and free paths remain unchanged.

WL127X_RFKILL disabled. Board selection accepts BT_WILINK built-in or as a
module; both use the same KIM platform data. With neither selected, the
existing rfkill platform data, initialization and registration are retained.

for built-in WiLink, modular WiLink and alternative rfkill; comparison of the
unchanged alternative branch; absence of removed helper references; existing
python3 tools/ti-st/kim_lifecycle_test.py; and git diff --check. These are host
and source checks, not kernel builds or hardware validation.

from this environment. Build shadow_cm11_defconfig with a compatible ARM

in a suitable environment. Source checks do not establish build success.
